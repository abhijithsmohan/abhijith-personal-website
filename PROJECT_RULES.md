# Abhijith Personal Website — Project Rules

## 1. Project Identity

Website:
https://abhijithsmohan.in

Person:
Abhijith S Mohan

Primary positioning:
Entrepreneur & Business Builder

Core territory:
Marketing × AI × Technology × Business

The website is a long-term personal-brand headquarters, professional identity, knowledge hub, project/case-study database, discovery engine, and business opportunity gateway.

## 2. Brand Voice

Use:
- confident but grounded
- ambitious but credible
- curious
- builder-oriented
- analytical
- practical
- transparent
- young but serious

Avoid:
- guru positioning
- fake authority
- generic motivational content
- empty business quotes
- fake success stories
- exaggerated AI claims
- unsupported achievements
- hustle-culture language

The positioning should communicate:
"I am figuring things out, but I am actually building."

## 3. Factual Accuracy

Never invent:
- job titles
- founder/co-founder status
- ownership
- clients
- partnerships
- metrics
- revenue
- growth percentages
- testimonials
- awards
- certifications
- project outcomes
- evidence
- dates
- responsibilities
- technologies used
- published work

When evidence is unavailable, use an honest placeholder or leave the claim out.

## 5. Design System

Design direction:
Founder Editorial

Characteristics:
- dark-first
- editorial
- professional
- human
- technology-aware
- premium
- restrained

Avoid:
- excessive cards
- excessive gradients
- 3D effects
- cursor gimmicks
- parallax
- sound
- unnecessary animation
- overly technical/developer aesthetic
- visual clutter

Prioritize:
- typography
- whitespace
- hierarchy
- readability
- editorial storytelling

## 7. Content Architecture

The website should connect:

Person
→ Work
→ Projects
→ Knowledge
→ Topics
→ Services / Collaboration

Projects should connect to relevant topics and knowledge.

Knowledge should connect back to relevant projects and topics.

Internal linking should strengthen the overall entity and topic structure.

## 8. SEO / Entity Principles

The long-term goal is:

Name Authority
→ Topical Authority
→ Project Authority
→ Commercial Discovery

Do not promise rankings.

The canonical personal entity is:

Abhijith S Mohan
https://abhijithsmohan.in

Use structured data only when the underlying content is real and supported.

Do not create fake Organization, Service, Event, Course, FAQ, JobPosting, or other schema merely for SEO.

## 9. Evidence

Evidence architecture:

Claim
→ Evidence
→ Verification
→ Approved Usage

Evidence may include:
- live URL
- code repository
- client testimonial
- metric log
- case-study document
- internship documentation
- published article
- verified portfolio asset

Never fabricate evidence.

If evidence is not yet organized, use a clear placeholder.

## 10. Development Rules

Current stack:
- Next.js
- TypeScript
- React
- Tailwind CSS

Before coding:
- inspect the existing implementation
- read relevant local Next.js documentation as required by AGENTS.md
- understand existing patterns
- avoid unnecessary dependencies

Do not add:
- database
- CMS
- authentication
- API
- external service
- dependency

unless explicitly required and approved.

## 11. Preservation Rules

Do not unnecessarily modify working pages.

When changing one project page, avoid affecting other approved project pages.
